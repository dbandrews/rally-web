# Race rules and stage data of the ported stages (race builder)

Scope: `src/game/**` (race controller, timing, pacenote caller, best times), `src/world/portedDefs.ts`,
`portedBuilder.ts`, `portSpline.ts`, `portedPacenotes.ts`, `src/world/ports/**` (generated by
`research/tools/port_tracks.py`), `tools/all-stages.mjs`. Addresses are `original_version/original_desktop_version.exe`.

## 1. Start: spawn grid, trigger 0, the clock

**Event triggers** (`Play.con`: `race.setEventTriggerSystemMode 1`, `race.addEventTrigger <played 0> <type 0> <dist>`,
exec 0x446830 / 0x446a00 → race vt+0xe8 = 0x4a3740 → FUN_00747f70, 12-byte entries {played, type, dist} at race+0x174).
Every archive writes type 0. At race setup FUN_0048c060 rebuilds them into a typed list (race+0x770):

| archive trigger | point-to-point | lap circuit (`race.laps` N, lap length L = spline length) |
|---|---|---|
| 0 | type 0 **start**; race+0xa14 = dist − 1 | lap 0: type 0 start; lap n ≥ 1: type 2 **lap line** at dist + n·L |
| 1 … k−2 | type 1 **checkpoint** | type 1 checkpoint at dist + n·L (every trigger after 0) |
| k−1 | type 3 **finish**; race+0xa10 = dist | — (finish = trigger 0 + N·L, type 3) |

The per-player tracker update FUN_004b4170 (dt per frame): race time += dt from the start of the running state;
FUN_00483470 consumes the next trigger when `trigger.dist < routeDistance && |lateral| < 20` (else it waits, the index
stays); the switch handles type 1 (split = time − lap start), 2 (lap time, lap count + 1) and 3 (finish, state 4) and
has **no case for type 0**: the start trigger is an event that times nothing. The clock runs from GO.

**Spawn**: race.spawnGrid `<s>/<lateral>/<spacing>` (exec 0x446dc0 → race+0x22c). The placement loop 0x484769 puts car
i on the centre spline at s (heading to the spline point s + 1 m, wrapped by the spline length); with more than one car
the columns alternate ∓lateral and every second car steps `spacing` back. Single player: the centre line at s.
Three archives spawn PAST trigger 0 — corsica2f 559 vs 545, hillclimb3af 54 vs 40, hillclimb3br 237 vs 200 — and their
`race.splineRange` starts between the two (550 / 48 / 220). The old port put the car at trigger 0 (and the game 8 m
behind it), outside that range: an `outOfRange` reset at GO.

Port: `SPAWN_S` = spawnGrid s (`SPAWN_GRID` verbatim); `Stage.startPose` is at the spawn and the stage object carries
`spawnS` (`portedBuilder.withSpawn`); `RaceController.gridPose` uses it (the procedural stages keep
`START_GRID_BACK_M`). `startS` stays trigger 0 (the start gantry and the zero of the route distance; a car that spawns
past it starts with a positive route distance, which changes no split: the gates are absolute distances, as the
original's triggers).

**Countdown**: 3 s (`COUNTDOWN_S`). Not re-verified: the HUD binds `HUD/raceCountdownTime` to HUD +0xa8 (0x4af306;
−1 when idle, 0x4afb61) but no direct writer of that field exists in 0x480000-0x4c0000 (it is written through a pointer
or from outside the race code). The one race-object `3.0f` store (0x4a5014, +0xa50, FLT_MAX in mode 7) belongs to a
vector field rewritten at 0x49cfe3, not a timer. `race.distance` (Play.con, e.g. corsica2f 5470) is a float console
variable (registered at 0x43f720) whose reader was not traced; it disagrees with the finish on several archives
(kenya3 5900 vs a 4010 m finish), so it times nothing and is not ported. Supporting the 3 s: the menu archive has
exactly four countdown images `menu/Texture/count3.tga … count0.tga` (3, 2, 1, GO) and `menu/Sound/CountDown.ssc`
two patches, `General/3,2,1.wav` (one 1.14 s beep, played per count) and `General/go!.wav`.
**False start**: the original has none (no "false/jump/early start" or "penalty" string in the exe or
`localestrings.str`; the car is parked by the player state machine until state 3, FUN_004b3790). **Joker laps**: none
(no "joker" string, two triggers per lap; research/study/controls_camera.md §5.4).

**Finish → track braking**: the finish trigger (FUN_004b4170 case 3) sets player +0x1dd and state 4; FUN_004b3790
state 4 then sets the physics' +0x44 flag, the post-finish braking drag scaled by `Physics.bodyBrakingFactorForTrack`
(every Play.con: 0.4, hillclimb3cf 0.1; MECHANICS_SPEC §2.7). Ported: `BODY_BRAKING` per archive (port_tracks.py) →
`stage.trackBraking` (`withSpawn`) → `RaceController.finish` calls `car.setTrackBraking(factor)` (ICarSim, optional
method); `car.reset` (a new race, a reset) switches it off. The procedural stages carry no factor and keep the
car as before.

## 2. Distances: 3-D arc length, verbatim, the centre line extended past a late finish

Every race distance (spawn, triggers, valid range, pacenotes) is the 3-D arc length along the evaluated AI centre
spline from t = degree. Earlier ports shifted all distances of an archive back when its finish lay within 45 m of (or
past) the spline end. The pacenotes prove the distances are right unshifted: the direction word of each call against
the turn of the road 80-140 m further on agrees 0.80 at the archive distances on hillclimb-1c-r but 0.30 shifted back
156 m (hillclimb-2a-r 0.71 vs ≈ 0.4, hillclimb-2b-f 0.82 vs 0.5). hillclimb1cr times its finish at 3631 m on a 3520 m
spline (its collision road runs on); `portedRoadSection` therefore EXTENDS an open centre line straight along its end
tangent (grade clamped to ±8 %) to the last trigger / pacenote + 60 m (`portedReach`). Shift is always 0.

## 3. Valid range and the hand-of-god reset (FUN_004b3e50)

Checked every frame while running, against the stage spline only (so it works the same on the original collision mesh:
off the mesh nothing is hit, the car falls and the height rule catches it):
`|lateral| > 30` (player+0x17c; a flag +0x6f, cleared when running, swaps this for the road-edge test vt+0xa0/0xa4),
`heightOffset < −5` (+0x180), `s < validLo` or `s > validHi` (+0x174/+0x178), or a manual request. Defaults
(0x4a2a98…0x4a2ab2): lo −FLT_MAX, hi +FLT_MAX, 30, −5 — so the lap circuits (no splineRange) are never out of range.
The fade's midpoint calls FUN_0074d980(20, lo + 1): back 20 m, **not before the range minimum + 1** (the spec's
"startDistance + 1" is this minimum), then 100 settle steps. Lap circuits go straight back 20 m, across the lap line too.

Where the player's range comes from: `race.splineRange` is stored by 0x4a31f0 at race-logic +0x50/+0x54 (ctor defaults
∓FLT_MAX, 0x4a2a98) and read back by 0x4a3210 (`lea eax,[ecx+0x50]`, race-logic vtable 0x806b58 slot 0x58); the player
range setter 0x4b4c30 copies a pair to +0x174/+0x178 (a vtable entry at 0x807774: slot 0x58 if that vtable starts at
0x80771c, not confirmed). The race setup passes a
pair from the race object's slot 0x12c to that setter (0x4a4c29-0x4a4c32); that this pair is the splineRange is
INFERRED (the caller's object has another vtable), as in research/study/controls_camera.md §5.4. Trigger 0 − 1
(race+0xa14, FUN_0048c060) is copied to race+0xa0c (0x485004) and does not reach +0x174.

Range used by the race: a ported point-to-point stage carries the archive's `race.splineRange` VERBATIM as
`stage.validRange` (`portedRaceSettings`); `RaceController` (`rangeOf`) uses it for the out-of-range check and the
reset floor, so corsica-2-f resets a car that backs out of its spawn past 550 and puts a reset no further back than
551, as the original. On corsica-2-f (550), hillclimb-3a-f (48) and hillclimb-3b-r (220) the minimum lies past
trigger 0; the Stage contract (tests/contracts/world.test.ts) accepts that because the spawn pose is inside the range.
MECHANICS_SPEC §5.4 gives the reset target as `max(s − 20 m, validRangeMin + 1 m)` (verified: `fld [esi+0x174];
fadd 1.0; push 20.0; call 0x74d980` at 0x4b3f0b-0x4b3f25).

The automatic checks use the stage spline only (`Stage.project`: lateral, height above the centre line, s), never the
world: on the original collision mesh a car that leaves the mesh hits nothing, falls, and the −5 m rule resets it; a
reset lands on the level under the pose (`liftAboveGround` passes the pose height as `yHint`), so a fall next to a deck
puts the car back on the road, not on the deck (tests/game/startRules.test.ts).

## 4. Pacenotes (PaceNotes.con)

`race.addPaceNote <kind 0> w1..w8 <distance>` (FUN_0074b470, 0x28-byte entries), 36 archives (none on the lap
circuits), 860 notes, word ids 1..41 = `Sound_PaceNotes.con` samples (research/formats/sound.md §10). Ported verbatim
in file order into `ports/<id>.ts` `PACENOTES` (distances exactly as written, e.g. 75.3601; the CVs stay mm-quantised);
`Pacenote.origWords` = the ids, `text` = the phrases written out. An independent check (a Python parser over every
`Play.con` / `PaceNotes.con`, case-insensitive file names) matches all 48 modules: triggers, spawn grid, splineRange,
laps, tyre, the 860 notes and their word lists, `BODY_BRAKING`.

Runtime (FUN_0074b620 from the HUD update 0x4b0415): scanning the list BACKWARDS, the first note with
`dist ≤ playerDistance` is the candidate; if already played nothing happens, else it is marked played and spoken only
when `|lateral| < 20` (a note passed further out is lost — the port used to defer it; fixed in `PacenoteCaller.update`).
The played flags are cleared only by `resetPaceNotes` / FUN_0074b680 (restart, lap events: 0x4afdc7, 0x4b0152); a
hand-of-god reset leaves them as they are. The port did mark every note up to the reset point as played; it now keeps
the flags (`RaceController.teleportBack`) and clears them on a 'restart' reset: identical for every note the car passed,
and a note jumped over within one step (never the last passed one, so never marked) fires on the next pass, as in the
original.
Because the scan is in file order, a note followed by an earlier-distance note can never fire (newzealand3f 2237.6 before
2136.67). `effectiveOrder` drops exactly those; the remaining list is strictly increasing and the "last note with
s ≤ pos" binary search equals the backward scan (Stage.pacenotes stays sorted, the contract).

Derived: direction / severity from the first bend word (easy 5, medium 4, hard 3, square 2, hairpin / tight hairpin 1),
modifiers from the hazard words, `cornerS` = the first analysed corner of that direction beginning 15-260 m after the
call, else call + 100 m (the measured lead, sound.md §10). Check: pooled over the 36 stages the direction words agree
0.71 with the road's turn 80-140 m after the call (sound.md's verifier: 0.71); a mirrored stage scores 0.29.

## 5. Stage frame

The archive CVs are in the original frame = rally-web SIM; three = (x, y, −z) (ASSETS.md §3). The ported stages were
built from the raw (x, z) as THREE coordinates — every stage was the original mirrored (left / right swapped, the
collision / track / object meshes only fitted mirrored, docs/orig/collision.md §5). `portSpline.origToThree` now
negates z before the centre line is built; tests/world/portedBounds.ts follows.

## 6. Grade separations (corsica 3: an 8 m overpass)

The procedural ground is single-valued: on a ribbon footprint the TOPMOST ribbon is the surface and the ribbon edges
hang 50 m kerb faces. Under the corsica 3 deck (s ≈ 3945 below s ≈ 4185, 8 m apart) the lower road's wheel rays started
"underground" against the deck and the deck's kerbs walled the lower road off. `CrossingZones` marks 4 m cells around
road samples that are far apart along the road (≥ 40 m), within 6 m in plan and > 2.5 m apart vertically; only there
`PortedGround` answers per level — the WorldQuery yHint rule for point queries (highest ground at or below yHint + 1 m,
else the lowest above; no hint = topmost, unchanged), a ray origin is underground only against the level of its own
height, the terrain counts only for rays starting above it, and a kerb hit more than 2.5 m below the ribbon above it
(an upper deck's) is passed through. Everywhere else the world is bit-identical to ground.ts. `liftAboveGround` passes
the pose height as yHint (a reset under the deck lands on the lower road). With the collision part built the original
mesh world (src/world/orig) answers natively.

## 6a. Road material of the procedural ported world

The procedural world of a ported stage (no collision part built, `?collision=0`, or off the mesh) used to paint its
road from a per-family "mix" (a base surface plus randomly placed accent stretches). It now takes the ORIGINAL road
material: `port_tracks.py road_material_runs` hits Track.gcm (the collision mesh the game uses) from 2 m above the
AI centre line every 2 m of 3-D arc length (6 m vertical segment, nearest face, `fmt_gcm.Gcm.raycast` = the 0x595c50
port) and writes the run starts `ROAD_MATERIAL: [s, gcm byte]`; `portedBuilder.origRoadMaterials` maps the bytes
through `materialFromOrig` per 1 m road sample (before the first run: the first; samples off the mesh, i.e. the spline
beyond the original's corridor, extend the neighbouring run). The centre spline lies on the road (median |dy| < 0.06 m
on every archive). Result: corsica 1 / 2f / 3r ASPHALT (+ GRAVEL stretches on 2 and 3), corsica 2r / 3f WATERASPHALT
(`water`, "wet tarmac") + GRAVEL, hillclimb 1-2 GRAVEL, hillclimb 3 SNOWASPHALT, ice ICEASPHALT, kenya SAND + ASPHALT /
COBBLES / GRAVEL / WOOD (bridges), newzealand MUD (+ WATERASPHALT on 1r, MUDGRASS), rallycross ASPHALT + GRAVEL / MUD.
The family mixes stay only for an archive without runs (none ship). One material per sample across the road width
(the procedural road has no per-lane material); the verges' own materials (GRAVELGRASS, SANDDEEP, ...) come from the
mesh only. An independent re-implementation over `.cache/original/*/Mesh/Track.gcm` gives the same runs on all 48.

## 7. Best times and ghosts

Keyed by the original car (`begin(…, { origCar })`, RaceSelection.car) or else the archetype:
`rally-web:best:v2:<stage>:<seed>:<car>` / `rally-web:ghost:v2:…` (unchanged format; `BestRecord.car`). The ghost's
CarRenderState carries `origCar`.

## 8. Autopilot on the original worlds

The original never drove a physical car along its rally AI splines (the opponents are split-time tables,
research/study/controls_camera.md §5.3), and hillclimb 1C's sparse spline runs through its service park (a truck and
a tent 20 m before the finish). The autopilot (a test tool, not the original's AI) takes the stage's WorldQuery
(`autopilot.world`, set by main.ts after `race.begin`) and plans around the colliding objects ahead (2026-10-30, was one
lateral offset for the whole 15-70 m window): it scans out to the stopping distance, groups the blocking objects into
clusters, picks a free lateral line per cluster, holds it through the cluster and caps the speed for each lane change
and narrow gap (src/game/autopilot.ts header; `avoidLateral` / `avoidClusters` in its debug state). Without a world
it follows the centre line as before. The obstacle cylinders (`obstaclesNear`) are only avoidance hints on mesh
worlds; the car itself collides through the ported object pass (docs/orig/collision.md §4).

## 9. tools/all-stages.mjs

Default set: the 48 ported stages (`--stages procedural|all|<ids>`). Per-stage sim cap: race distance / 8 m/s + 60 s,
≥ 600 s (`--max-sim` overrides; iceracing-1-r 5 × 1923 m → 1262 s, rallycross-1-r 1660 s). `--list` prints the set;
`--out`, `--drive`, `--query k=v` (forwarded to the drive script; tools/drive.mjs adds it to the game URL, e.g.
`--query collision=0`). `--shot-every` (default 10 s of sim):
drive.mjs renders on every 0.25 s step chunk and headless SwiftShader queues that GPU work; with its 30 s default the
first screenshot on the heavier procedural stages waited out ≈ 120 queued frames (kettle-park 31.8 s, Playwright's
limit is 30 s) and failed the run; 10 s drains the same work in smaller pieces.

Results (awd_wrc, autopilot, stepped): the 48 ported stages on the default worlds (collision part built: the original
mesh) all finish with 0 resets, 0 console errors, min clearance ≥ 0.32 m, max |lateral| ≤ 6.7 m (hillclimb-1c-f's
service park), e.g. corsica-2-f 3:43.43, corsica-3-f 2:39.44 (under the deck at 0.44 m clearance), hillclimb-3a-f
4:38.13, hillclimb-3b-r 4:51.70, iceracing-1-r 10:19.29 (cap 1262 s), rallycross-1-r 8:58.52. The same 48 on the
procedural ported world (`?collision=0`, original road materials) all finish with 0 resets, times within 0.9 s of the
mesh runs except hillclimb-1c-f (3.9 s faster; likely the original service-park object proxies, §8, which only the
collision part provides). The 7 procedural stages pass too (`--stages procedural`).

## 10. Not done / open

  finish) or uses a different parameterisation on the sparse hillclimb1c spline (71 CVs, control polygon 4035 m).
* The writer of raceCountdownTime (the 3 s countdown is supported by the four count3..count0 images and the
  3,2,1 / go! patches, not by code).
* race.distance (a float console variable; reader not traced) and race+0xa0c (trigger 0 − 1) are not ported.
* The splineRange → player +0x174 link is INFERRED (§3).
* The pre-running road-edge lateral check (+0x6f) and the AI stuck rule are not ported.
